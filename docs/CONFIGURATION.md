# 参数配置

工程将应用调校集中为配置头，算法数据通路、状态机、接口和存储组织位于对应 RTL。结构参数、时钟、协议、图像尺寸及已发布模块的基础配置继续由模块定义管理。

| 配置头 | 用途 |
|---|---|
| `A_board/lab_ex3_osd/user_source/hdl_source/mode38_local/fpga_a_public_tuning.vh` | SAD 评分、接受条件、候选差值与模板学习速率 |
| `A_board/lab_ex3_osd/user_source/hdl_source/fpga_motion_example_config.vh` | 差分与面积门限、背景更新、去噪投票、目标保持与关联、静止判定及显示平滑 |
| `B_board/GM6020_test/user_source/fpga_b_example_config.vh` | 几何映射、模型控制、跟踪增益、限幅及滤波 |

这些文件提供独立的示例配置，不代表原机的实测标定或调优结果。几何示例采用简单线性映射，控制示例中的反馈增益设为零；加载源码不等于已经完成执行机构调试。按实际相机、安装位置、电机和采样周期重新配置后，再验证闭环行为。

## 配置方法

1. 将 A 板的 `user_source/hdl_source`、`user_source/hdl_source/mode38_local` 和 B 板的 `user_source` 分别加入各自工程的 Verilog include 搜索路径。
2. 根据应用修改示例宏。每个宏独立使用 `ifndef` 保护，也可以在读取 RTL 前预定义同名宏覆盖示例值。
3. 保持宏的位宽、符号和定点格式。部分 A 板宏表示移位、布尔判断或平滑计算表达式，需结合调用表达式理解，不能只填一个裸数字。背景示例采用当前灰度直接更新；修改平滑系数时应保持写回值的尺度。
4. B 板宏名包含模块、参数类别和出现序号。同一物理模型在默认参数、顶层覆盖和双轴包装中可能有多个入口，应一起核对。
5. 各时钟域只在其既定提交边界消费配置或结果。改变控制周期、采样率、坐标格式时，重新验证整个链路的数值和时序契约。

运动模块的默认参数与系统顶层覆盖分别有具名配置入口。调整差分阈值、面积或增益稳定等待时，同时核对实例覆盖；不要只改模块默认值。网格尺寸、目标槽、标签容量、接口位宽和存储地址等结构仍由 RTL 管理。底盘积分系数在顶层及两个轮速包装中共用同一个配置宏，确保默认值与集成路径一致。

本地部署配置可放在忽略的 `config.local.vh` 或 `.local/` 目录中，通过项目宏定义或预包含方式载入。不要同时编译多份不同版本的模块；两个板卡分别维护工程和编译单元。

## 建议验证

先对单模块检查复位、零输入、正负边界和限幅，再验证帧边界、取消与忙时请求。几何映射需检查目标区域内的坐标和雅可比，电机控制需先核对反馈方向和输出量程。闭环验证从低输出限制开始，分别记录误差、超调、稳定时间与丢失后的状态交接。

源码解析、原配置回代和工程依赖检查用于验证发布改动的范围，不证明示例配置的识别精度、控制稳定性或上板时序。
